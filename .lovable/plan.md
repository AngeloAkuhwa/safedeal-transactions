# Fix: "Failed to fetch" when inviting a new internal user

## Root cause (verified)

The Access Control "Add User" drawer calls `supabase.functions.invoke("admin-invite-internal-user", …)` from `src/services/admin-access-control.service.ts` (lines 830 and 1345), but **no edge function with that name exists** under `supabase/functions/`. The browser network log confirms two POSTs to `/functions/v1/admin-invite-internal-user` failing with `Failed to fetch` (function not deployed → no CORS response). `resendInternalUserInvite` calls the same missing function.

## Fix

Create `supabase/functions/admin-invite-internal-user/index.ts` that:

1. Handles CORS preflight (`OPTIONS`) and only accepts `POST`.
2. Authenticates the caller via the shared `requireAdmin(req)` helper and rejects non-admins.
3. Validates the body with Zod: `first_name`, `last_name`, `full_name`, `email`, `department`, `roles[]`, `primary_role`, optional `team`, `job_title`, `reporting_manager_id`, `access_expires_at`, `reason`, `send_invitation`, `require_2fa`, `resend?`.
4. Enforces server-side rules:
   - `primary_role` must be in `roles`.
   - Reject if email already exists in `internal_users` (unless `resend: true`, in which case load the existing row).
5. Invite path (new user):
   - Call `admin.auth.admin.inviteUserByEmail(email, { data: { full_name, default_role: primary_role } })` using the service-role client, with `redirectTo` set to the app origin.
   - Insert into `internal_users` (status `active`, `invitation_status: 'invited'`, employee_id auto-generated by the DB trigger, plus `first_name`, `last_name`, `department`, `team`, `job_title`, `reporting_manager_id`, `access_expires_at`, `reason_for_access`, `two_factor_enabled: require_2fa`).
   - Insert one row per role into `internal_user_roles`, marking `primary_role` with `is_primary: true`.
6. Resend path (`resend: true`): re-issue `inviteUserByEmail` for the existing email and update `invitation_status`/`updated_at`.
7. Audit via the existing `admin-log-access-action` pathway (or `logAdminAction` shared helper) with `action_type: "user_invited"` / `"invitation_resent"`, capturing IP + User-Agent through `extractRequestMeta`.
8. Return `{ user: <hydrated InternalUser row matching the shape the service expects> }` on success, or `{ error }` with an appropriate status on validation/permission failures. Always include `corsHeaders` on every response, including errors.

## Verification

- Deploy the function.
- From the Access Control page, submit the Add User drawer for a new email → expect 200, toast "Invite sent", row appears in the directory.
- Repeat with the same email → expect a clean 409/400 error, not "Failed to fetch".
- Trigger "Resend Invitation" from the row menu → expect 200 and a toast.
- Confirm one `admin_actions` row per action with `action_type = user_invited` / `invitation_resent` and IP/User-Agent populated.

## Out of scope

- No schema changes; `internal_users` and `internal_user_roles` already have every column used.
- No changes to the drawer UI or the service layer beyond what the function returns.
